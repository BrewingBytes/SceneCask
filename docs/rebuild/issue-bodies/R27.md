## Purpose

Generate spoiler-safe activity and friend recommendations. This delivers the social outcome described below without requiring knowledge of prior conversations.

## Relevant context

SceneCask is a responsive TV-tracking web app, not a streaming service. Rust/Axum API, Next.js/TypeScript, PostgreSQL/SQLx, REST/OpenAPI generated client, server cookie sessions, email/password plus Google SSO and TMDB. Track episodes independently, including future/out-of-order watches; only explicit catch-up marks earlier episodes. Backend removes protected content. The product must work without friends. Private by default; hosted discussions require mutual approved follows plus a separate spoiler gate. Completed is computed, never a manual status.

Read [approved decisions](https://github.com/BrewingBytes/SceneCask/blob/e524b2898965cfbbdd4b0aa049c0deb999900459/docs/rebuild/decisions.md), [architecture](https://github.com/BrewingBytes/SceneCask/blob/e524b2898965cfbbdd4b0aa049c0deb999900459/docs/rebuild/architecture.md), and [canonical contracts](https://github.com/BrewingBytes/SceneCask/blob/e524b2898965cfbbdd4b0aa049c0deb999900459/docs/rebuild/contracts.md). ## Implementation requirements

Project completed library/mark actions into deduplicated activity; no-op/replay duplicates absent, Undo removes corresponding events, bulk catch-up at most endpoint event if changed. Filter current follows/privacy/blocks at read. Recommend visible unsaved shows by followed-person count with deterministic ordering; empty no-friends result. Never store/return episode text in activity.

Follow the named canonical sections for exact entities, paths, payloads, status codes, validation, transaction ownership, permissions and redaction. Failure must preserve authoritative state; never expose protected strings or image paths in errors/logs/client payloads.

API example (full DTO/schema in the canonical contract):

- `GET /api/v1/activity`
- Request: `no body`
- Response: `200 {"items":[],"nextCursor":null} without eligible activity; populated episodes contain only id,season,number.`
- Error envelope: `{"error":{"code":"VALIDATION_ERROR","message":"Check the highlighted fields.","requestId":"uuid"}}`. Use the endpoint-specific HTTP status from C03–C08.

## Acceptance criteria

- Given no follows, recommendations/activity empty and personal APIs unchanged.
- Given later block/privacy revocation, old event no longer visible.
- Given mark retry/Undo, no duplicates and reversed event removed; only episode code exposed.
