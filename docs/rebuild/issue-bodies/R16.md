## Purpose

Persist individual watched changes and conflict-safe Undo. This delivers the tracking outcome described below without requiring knowledge of prior conversations.

## Relevant context

SceneCask is a responsive TV-tracking web app, not a streaming service. Rust/Axum API, Next.js/TypeScript, PostgreSQL/SQLx, REST/OpenAPI generated client, server cookie sessions, email/password plus Google SSO and TMDB. Track episodes independently, including future/out-of-order watches; only explicit catch-up marks earlier episodes. Backend removes protected content. The product must work without friends. Private by default; hosted discussions require mutual approved follows plus a separate spoiler gate. Completed is computed, never a manual status.

## Implementation requirements

Implement individual true/false marks for released/future/undated/special episodes, auto-save/status upgrade rules, revision/idempotency, mutation actions and per-field provenance. Implement10m action Undo with skipped conflicts and repeat outcome. Use same action bookkeeping interface as library writes; false rows retain revisions. History erase uses aggregate revision, explicit API and same Undo engine.

Follow the named canonical sections for exact entities, paths, payloads, status codes, validation, transaction ownership, permissions and redaction. Failure must preserve authoritative state; never expose protected strings or image paths in errors/logs/client payloads.

API example (full DTO/schema in the canonical contract):

- `PUT /api/v1/progress/episodes/{episodeId}`
- Request: `{"watched":true,"expectedRevision":0}`
- Response: `200 MutationResult with episodes:[{id,watched:true,revision:1}]; future release remains future. Idempotency-Key required.`
- Error envelope: `{"error":{"code":"VALIDATION_ERROR","message":"Check the highlighted fields.","requestId":"uuid"}}`. Use the endpoint-specific HTTP status from C03–C08.

## Acceptance criteria

- Given future episode, mark persists and metadata stays future.
- Given A:true B:false C:true, Undo A skips C despite matching value.
- Given repeated request key or Undo, no duplicate action/event; other user cannot undo.
