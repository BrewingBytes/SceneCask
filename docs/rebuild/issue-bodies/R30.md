## Purpose

Implement hosted discussions and gated comment reads. This delivers the discussions outcome described below without requiring knowledge of prior conversations.

## Relevant context

SceneCask is a responsive TV-tracking web app, not a streaming service. Rust/Axum API, Next.js/TypeScript, PostgreSQL/SQLx, REST/OpenAPI generated client, server cookie sessions, email/password plus Google SSO and TMDB. Track episodes independently, including future/out-of-order watches; only explicit catch-up marks earlier episodes. Backend removes protected content. The product must work without friends. Private by default; hosted discussions require mutual approved follows plus a separate spoiler gate. Completed is computed, never a manual status.

## Implementation requirements

List/create one host thread per episode, current mutual-follow privacy, spoiler metadata, paginated comments read. No protected content/participant counts in locked result. Special explicit reveal, undated gap locking, per-thread grants, participant block filtering, tombstones. Integrate existing reveal service permission decisions, no main router edits.

Follow the named canonical sections for exact entities, paths, payloads, status codes, validation, transaction ownership, permissions and redaction. Failure must preserve authoritative state; never expose protected strings or image paths in errors/logs/client payloads.

API example (full DTO/schema in the canonical contract):

- `GET /api/v1/discussions/{id}/comments`
- Request: `no body`
- Response: `403 {"error":{"code":"SPOILER_LOCKED","message":"Watch through this episode or explicitly reveal this discussion.","requestId":"uuid"}}; privacy failure404 instead.`
- Error envelope: `{"error":{"code":"VALIDATION_ERROR","message":"Check the highlighted fields.","requestId":"uuid"}}`. Use the endpoint-specific HTTP status from C03–C08.

## Acceptance criteria

- Given one-way host follow, thread absent; mutual still subject to watched-through.
- Given same-episode threads A/B, grant A does not reveal B.
- Given unrelated participant blocked, comments/identity/count contribution absent but host access preserved.
