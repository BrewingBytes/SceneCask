## Implementation requirements

Implement OIDC authorization-code flow with PKCE/state/nonce validation using maintained library, fixed Google discovery, verified email, safe callback/returnTo,10m flow expiry and single use. Use issuer+subject identity. Support signin/link/reauth intents, identity listing/unlink. Same email never auto-links. No long-lived Google tokens; prevent unlinking last method.

Follow the named canonical sections for exact entities, paths, payloads, status codes, validation, transaction ownership, permissions and redaction. Failure must preserve authoritative state; never expose protected strings or image paths in errors/logs/client payloads.

API example (full DTO/schema in the canonical contract):

- `GET /api/v1/auth/google/start?intent=signin&returnTo=/home`
- Request: `no body`
- Response: `303 to Google; validated callback303 to /home or /onboarding/profile. Equal email alone never links identity.`
- Error envelope: `{"error":{"code":"VALIDATION_ERROR","message":"Check the highlighted fields.","requestId":"uuid"}}`. Use the endpoint-specific HTTP status from C03–C08.

## Acceptance criteria

- Given valid new Google identity, create one private account/session; repeated subject signs into same account.
- Given matching email with unknown subject, require explicit authenticated linking.
- Given replay/wrong nonce/audience/state or last-method unlink, fail without account mutation.
