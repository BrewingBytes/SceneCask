# Canonical implementation contracts v1

Authority: decisions.md, then this contract and design/supplement.md, then prototype v2. Historical prototypes are reference only. These are implementation specifications, not application code. Issue R03 transcribes the API below into validated OpenAPI without changing behavior.

## C01 — Layout, ownership and checks

Use architecture.md paths. pnpm workspace and Rust workspace; pin supported stable toolchains and exact dependencies in R01, commit lockfiles. Cargo workspace root at services/api. Next.js App Router. API mounted at /api/v1 through same-origin reverse proxy. Production hosts are configurable, no vendor-specific requirement. SMTP abstraction and local mail capture; PostgreSQL worker polls durable outbox/jobs, no Redis required.

Root scripts: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm api:generate`, `pnpm api:check`, `pnpm test:e2e`. Rust: `cargo fmt --manifest-path services/api/Cargo.toml --check`, `cargo clippy --manifest-path services/api/Cargo.toml --all-targets -- -D warnings`, `cargo test --manifest-path services/api/Cargo.toml`. CI integration tests run against PostgreSQL, not SQLite. R01 defines commands; dependent issues run relevant commands plus generation drift check when applicable. No real-provider credentials in normal CI. Live Google/TMDB smoke checks are manual release evidence.

R02 owns all schema migrations and allocation 0001–0007; feature issues may not invent migrations. R03 owns contracts/openapi.yaml and generator configuration; feature issues implement it. Request contract/schema changes in a separate coordinated change before depending on them. Module/router registration belongs to integration owners listed in issues. Never revert other agents' edits.

No provider ID as a public app primary key. FK and uniqueness enforced in PostgreSQL. Lists use cursor ordering defined C03.

## C03 — HTTP conventions and examples

All paths below relative to /api/v1. JSON success objects unwrapped; paginated response `{items:[],nextCursor:null}`. Cursor opaque, validated, keyset order (createdAt,id) descending unless stated otherwise; limit default 20, max 50. UUID placeholders below are illustrative. Unknown properties rejected for mutation DTOs. Never return raw provider objects.

Errors: `{error:{code:"VALIDATION_ERROR",message:"Check the highlighted fields.",fields:{handle:"Use 3–30 lowercase letters, numbers or underscores."},requestId:"uuid"}}`. 400 malformed body/cursor; 401 AUTH_REQUIRED; 403 EMAIL_UNVERIFIED, CSRF_FAILED, SPOILER_LOCKED or OPERATOR_REQUIRED; 404 NOT_FOUND conceals inaccessible people/discussions/comments; 409 REVISION_CONFLICT, PREVIEW_STALE, IDENTITY_LINK_REQUIRED, IDENTITY_IN_USE, LAST_SIGNIN_METHOD; 410 TOKEN_EXPIRED or ACTION_EXPIRED; 422 VALIDATION_ERROR or INVALID_EPISODE_SCOPE; 429 RATE_LIMITED + Retry-After seconds; 502 PROVIDER_UNAVAILABLE; 503 SERVICE_UNAVAILABLE. Do not leak email existence in public auth errors. Request IDs contain no secrets.

Authenticated mutations require X-CSRF-Token paired to session, same-origin validation and JSON content type. Login/signup/reset also validate Origin; session bootstrap supplies a CSRF token. Progress/library/catch-up/history writes require Idempotency-Key UUID; retained 24h. Same key+body returns same response; changed body 409. Responses with viewer state use Cache-Control private,no-store. ETags not shared between users. Apply body-size limits and rate limits centrally; auth limits per IP+normalized identifier (5 attempts/minute, 20/hour), ordinary writes 60/minute/user, search 30/minute/user. These are configurable defaults.

Library action provenance is shared with the tracking mutation service: implement a shared action recorder in R15 and extend it in R16; idempotency records and action changes commit in the same transaction as domain writes. tracking_show_state.revision increments on every effective watched write/reversal and is used by history erase and catch-up. Progress mutations serialize on that user+show row; catch-up locks catalog revision too, in a consistent show→tracking→library→episode order.

Every endpoint below declares request → success status/body and exceptional cases. Omitted GET body means no request body. Auth required unless explicitly public; email verified required for catalog/personal/social APIs. SSO callback and email-token exchange are not exempt from their own state/token validation.

### C04 — Authentication and profile

- GET /session (public): 200 `{user:null,csrfToken:"..."}` or `{user:{id,email,displayName,handle,visibility,verified:true,role:"member"},csrfToken:"..."}`. Anonymous CSRF cookie is not an authenticated session.
- POST /auth/register `{email,password}` → 202 `{message:"Check your email."}` for new or existing email; queue verification only for eligible unverified registration. Password 12–128 characters, no arbitrary composition rule; never trim password. Normalize email trim+casefold, no plus/dot rewriting. Pending users cannot access libraries. Existing verified accounts unchanged.
- POST /auth/verify `{token}` → 200 session DTO and rotated cookie; single-use token valid 24h; expired/replayed → 410 with resend action.
- POST /auth/verification-resend `{email}` → 202 same generic message; invalidate previous verification token, 60-second resend cooldown.
- POST /auth/login `{email,password}` → 200 session DTO or generic 401 INVALID_CREDENTIALS; unverified correct credentials → 403 EMAIL_UNVERIFIED and verification screen, no application session. Argon2id password hashing; offload expensive work from async executor.
- POST /auth/logout `{}` → 204, revoke session+grants, expire cookie. Already logged out also 204.
- POST /auth/password-reset-request `{email}` → 202 generic check-email message; reset token expires 30m, single use.
- POST /auth/password-reset `{token,newPassword}` → 204; invalidate all sessions/grants and prior tokens; requires fresh login. Expired/replayed → 410. An SSO-only verified user may establish a password by proving mailbox control here.
- GET /auth/google/start?intent=signin|link|reauth&returnTo=/home (signin public) → 303 Google authorization URL. Store single-use state/nonce/PKCE and intent, lifetime 10m. ReturnTo allowlisted same-origin path only.
- GET /auth/google/callback?code=...&state=... (public) → 303 /home, /onboarding/profile or account/signin error route. Validate state, PKCE, nonce, issuer, audience, expiry and signature through a maintained OIDC library and discovery/JWKS. Scopes openid email profile only; no Google API access/refresh token retention. Require verified email for new account. Subject identifies account, never mutable email. Matching existing email with unknown subject → link-required UI, not auto-merge. Link requires current authenticated account and fresh reauthentication. Cancellation returns recoverable UI and no session. Reauth intent must match current account identity.
- POST /auth/reauth `{password}` → 204 marks current session reauthenticated now; invalid → generic 401. Google-only users use Google reauth intent. Freshness 5m for link/unlink/delete.
- GET /me/identities → 200 `{passwordEnabled:true,googleLinked:false}`. DELETE /me/identities/google → 204 with fresh reauth; 409 if last sign-in method. Does not delete account.
- PATCH /me `{displayName:"Ana",handle:"ana_r"}` → 200 user DTO. Name 1–80 chars, handle 3–30 lowercase ASCII letters/digits/underscore, unique (409 HANDLE_TAKEN). Handle immutable after first choice in initial scope; subsequent different handle 422. No user-controlled operator role. Email change/avatar uploads out of scope; initials avatars.

Cookies: __Host-scenecask, Secure,HttpOnly,SameSite=Lax,Path=/; dev-only localhost exception documented. Idle expiry 7d, absolute 30d; rotate on authentication. Reveal grants expire after 12h at most and always on logout/reset/session expiry; described in UI as this sign-in session. Auth pages use no-referrer and no third-party resources with token query strings; scrub token after exchange.

## C05 — Metadata, library and progress API

- GET /shows/search?q=hollow&page=1 → 200 `{items:[{provider:"tmdb",providerId:123,title:"Hollow Orchard",year:2024,genres:["Drama"],posterUrl:null}],page:1,totalPages:2}`. q trimmed 2–100 chars, page 1–500. Search only TV; provider errors 502 with retry, cache query 15m server-side. No automatic import of each search result.
- POST /shows/import `{providerId:123}` → 200 `{showId:"uuid"}`. Deduplicate simultaneous imports, import show+seasons+episodes transactionally; failed/incomplete initial import 502, no partial usable catalog. Existing recent import reused. Credentials server-only.
- GET /shows/{id} → 200 Show DTO (below); GET /shows/{id}/episodes?season=1&cursor=... → paginated Episode DTOs sorted season number,episode number,id ascending, limit 50. Explicit specials season=0.
- GET /episodes/{id} → 200 Episode DTO plus showId; unknown 404. Protected details absent until C07 allows.
- GET /library?status=watching&q=hollow&cursor=... → paginated LibraryItem; case-insensitive title search <=100 chars, status filter optional. Counts in `{counts:{all:2,watching:1,plan_to_watch:1,on_hold:0,dropped:0}}` across all saved entries before query. Saved_at,id descending.
- PUT /library/{showId} `{saved:true,status:"plan_to_watch",expectedRevision:0}` → MutationResult. Existing history retained; omitted status preserves existing choice or defaults plan_to_watch. Save false removes only saved flag, preserves progress/status. Conflicts 409. PATCH /library/{showId} `{status:"watching",expectedRevision:2}` → MutationResult; missing/not-saved entry 404.
- PUT /progress/episodes/{episodeId} `{watched:true,expectedRevision:0}` → MutationResult. ExpectedRevision checks that episode's progress; absent row revision=0. Future and undated allowed individually; specials allowed individually. True auto-adds show and upgrades plan_to_watch to watching but preserves on_hold/dropped; changes recorded under same action. False never adds show. Unchanged value with current revision returns no-op result and no activity.
- POST /shows/{id}/catch-up/preview `{throughEpisodeId:"uuid"}` → 200 `{previewId:"uuid",expiresAt:"ISO",through:{season:2,episode:7},included:[{id,season,episode}],excluded:{alreadyWatched:[],future:[],undated:[],specials:[]},count:4}`. Endpoint must be regular and belong to show, else 422. Preview expires 5m. Future endpoint allowed but future episodes excluded. Zero eligible changes is valid.
- POST /shows/{id}/catch-up `{previewId:"uuid"}` → MutationResult. Atomically verify user ownership, expiry, metadata revision and all relevant progress/library revisions, then mark only preview.included, auto-add/upgrade library as individual mark. Mismatch 409 PREVIEW_STALE, expired 410. No change may occur on stale/rejected requests. Never expand preview at commit time.
- DELETE /shows/{id}/history `{expectedRevision:7}` → MutationResult. expectedRevision is aggregate tracking revision from Show DTO; set every watched episode including specials false, preserve saved flag and manual status. Require separate confirmation; revision mismatch 409.
- POST /actions/{id}/undo `{}` → 200 `{actionId:"uuid",reverted:3,skipped:1,library:LibraryItem}`. Author only, otherwise 404. Valid 10m; UI success toast lasts 6s. For each change revert only when after_revision is still current. Increment revisions for reversal, never restore old revision. All matching reversals atomic; repeated undo returns stored outcome; expired 410. Remove activity events associated with reversed watched/add fields. Undo never reverses notification delivery or block operations.
- GET /home → 200 `{upNext:[LibraryItem],caughtUp:[LibraryItem],libraryEmpty:false}`. Only saved watching shows populate sections; libraryEmpty is based on all saved entries. Empty watching section with other saved shows says "Choose a show to watch" and links Library. featured is first in saved_at,id order; no personalization algorithm.

Show DTO: `{id,title,year,genres,synopsis,posterUrl,status,catalogRevision,metadataStale:false,releaseInfoIncomplete:false,seasons:[{number,count}],library:LibraryItem|null,trackingRevision:7}`. Series synopsis must be general series synopsis, never episode overview. Missing artwork uses local placeholder.

Episode DTO locked: `{id,showId,season:1,number:3,release:{state:"future",date:"2026-11-12",timezone:"UTC",estimated:true},watched:false,revision:0,detailsAccess:"locked"}`. Unlocked adds `details:{title:"...",overview:"...",stillUrl:null}`, detailsAccess watched/revealed. No protected keys, URLs or text outside details. Preserve future label after watched marking.

LibraryItem: `{showId,title,year,posterUrl,saved:true,status:"watching",revision:2,progress:{watched:2,total:6,percent:33,state:"in_progress",nextEpisode:{id,season:1,number:2},outOfOrder:true,releaseInfoIncomplete:false}}`. Progress next never contains title/still. State: in_progress/caught_up/completed/not_yet_available/release_unknown. Count all active regular episodes in total and marked active regular in watched, including individually marked future/undated; specials excluded. Empty total → percent 0. No released episode → not_yet_available if future dates exist, else release_unknown. Completed takes priority if complete catalog, ended/canceled, all active regular marked, total>0, no undated episodes (even if future episodes were individually marked). Otherwise any released unmarked → in_progress; released all marked → caught_up. New releases recalculate on read using server clock without requiring a browser refresh job; metadata refresh discovers new episodes.

MutationResult: `{actionId:"uuid"|null,undoUntil:"ISO"|null,changed:1,library:LibraryItem,trackingRevision:8,episodes:[{id,watched:true,revision:1}]}`. No-op changed=0, actionId/undoUntil=null. Responses reflect authoritative server state. Optimistic client must not unlock protected data before successful authorized fetch. Unknown write outcome is retried with same idempotency key; known rejected retry after editing uses a new key.

Metadata refresh: worker scans saved shows every 24h, batches with bounded concurrency, respects 429/Retry-After, retries 5xx with jitter; failed refresh retains last-good data and marks stale after 48h. No SLA promises. Never use production credentials in CI. Provider data includes no authoritative streaming time guarantee. Attribution/footer uses TMDB-approved logo/text and link per official requirements. Do not expose TMDB key in image URLs.

## C06 — Social and privacy API

Beta endpoints disabled behind server feature flag (404) until beta enabled; hide UI too. All social access is authenticated. Public means any signed-in member may see profile library/activity, not anonymous search-engine exposure. Private profile card (id, handle, displayName, initials, visibility, relationship) is discoverable, but library/progress/activity require approved follow. Block in either direction conceals both people from search/content except own block-management entry.

- GET /people?q=ana&cursor=... → paginated Person DTO sorted handle,id ascending; query 2–100, search handles/display names only, never email.
- GET /people/{id} → 200 `{person:Person,canViewLibrary:true}`. GET /people/{id}/library → paginated LibraryItems without internal revisions; 404 if forbidden. Episode details follow viewer progress, never subject progress.
- POST /people/{id}/follow `{}` → 200 `{state:"pending"|"approved"}`; private pending, public immediate. Self 422; blocked 404; repeat idempotent. Pending creates one notification/outbox event, retries cannot duplicate.
- DELETE /people/{id}/follow → 204 cancels pending or approved. No reapproval needed for remaining reverse edge. Access revoked immediately.
- GET /me/follow-requests → paginated Person list. POST /me/follow-requests/{requesterId} `{decision:"approve"|"decline"}` → 204. Not currently pending 404. Decline sends no notification.
- GET /me/followers → paginated Person list; DELETE /me/followers/{id} → 204 remove incoming edge, no automatic notification.
- PATCH /me/privacy `{visibility:"public"}` → 200 `{visibility:"public"}`. UI explicit warning; pending requests remain pending until approved/withdrawn (no silent batch conversion). Switching private retains existing approved follows; public nonfollowers lose library/activity access immediately.
- GET /me/blocks → paginated `{id,handle,displayName}`; PUT /me/blocks/{id} `{}` → 204 atomically add block and remove follow/request edges both ways, cancel associated pending notifications, revoke affected discussion grants. DELETE /me/blocks/{id} → 204 unblocks only, does not restore follows. No block Undo toast; offer unblock in settings.
- GET /activity?cursor=... → paginated `{id,actor:Person,kind,show:{id,title,posterUrl},episode:{id,season,number}|null,createdAt}` from approved follows, rechecked at read. No comment excerpts/titles/stills. Do not emit bulk catch-up hundreds of events: one event for endpoint only if that endpoint changed; duplicates/no-ops produce none.
- GET /recommendations?cursor=... → `{items:[{show:{id,title,year,posterUrl},reason:{kind:"followed_people",people:[Person]}}],nextCursor:null}`. Aggregate visible saved shows of approved follows; exclude viewer's saved shows, blocked accounts and inaccessible libraries. Deterministic count-desc/showId tie-break ordering, snapshot cursor. No friends → empty recommendations with search CTA, not a fake social feed.

Person DTO: `{id,handle,displayName,initials,visibility,relationship:{outgoing:"none"|"pending"|"approved",incoming:"none"|"pending"|"approved",mutual:false}}`. Never expose private email or relationship edges of unrelated people.

## C07 — Discussion and spoiler API

Access = host OR current mutual approved follow with host, plus no host/viewer block, all checked at read/write. Public account does not make discussion public. Eligible participants may see other participants even when not following them; explain before entering/posting. Participant-to-participant block hides each other's comments and identities in returned comments/counts but does not revoke unrelated host access. Losing host mutuality revokes access immediately, including previously revealed threads. No permission snapshots on thread creation.

Episode detail gate: individually watched OR session grant for episode_details+episodeId. Regular discussion gate: all active regular episodes ordered through target watched OR session grant for discussion+discussionId. This includes undated/future predecessors; explain missing episode codes and offer individual marking or explicit reveal. Specials discussion always requires explicit reveal even if marked. Reveal does not mark anything or reveal another discussion.

- GET /episodes/{id}/discussions → paginated `{id,host:Person,isHost:false,access:"locked"|"watched"|"revealed",missingEpisodeCodes:["S1 E2"],isSpecial:false}`. List only privacy-eligible threads. Locked response contains no comments/previews/reaction counts or hidden participant identities. Counts on unlocked threads count visible comments only.
- POST /episodes/{id}/discussions `{}` → 201 `{id,access:"locked"}` or existing 200. Creates caller-hosted thread; progress not required to create; read/post still gated. Unique host+episode.
- GET /discussions/{id}/comments?cursor=... → paginated Comment, createdAt,id ascending. Privacy failure 404; spoiler lock 403 SPOILER_LOCKED, no body text. Comment `{id,author:Person|null,body:"text"|null,createdAt,removed:true|false,canDelete:true,canModerate:false}`. Deleted comments show tombstone and no original text; blocked/reported-by-viewer comments omitted.
- POST /discussions/{id}/comments `{body:"That ending surprised me."}` → 201 Comment. Trim 1–5000 Unicode chars; plain text only, escape output, no HTML/Markdown embeds, attachments, link previews or edits. Limit 10/minute/user. Access and spoiler gates apply to posting. Restrict discussion to its episode and earlier; later spoilers can be reported, not automatically classified.
- DELETE /comments/{id} → 204 for author, host, or operator; otherwise 404. Host only within own thread. Remove body, record removal, return tombstone. Repeat authorized deletion idempotent.
- POST /comments/{id}/reports `{reason:"later_episode"}` → 201 `{reportId:"uuid"}`; requires accessible/unlocked visible comment, one active report per viewer+comment; repeat returns existing. Hide for reporter immediately; does not remove globally.
- POST /reveals `{scope:"episode_details",resourceId:"episodeId"}` or `{scope:"discussion",resourceId:"discussionId"}` → 201 `{scope,resourceId,expiresAt}`; privacy check before grant. Grant tied to current session, max12h/session expiry. DELETE /reveals/{scope}/{resourceId} → 204. Hide again refetches redacted response and evicts protected client caches.

Privacy revocation always supersedes reveal. Frontend must invalidate relevant viewer caches on progress/undo, reveal/hide, logout/session expiry, follow/block/privacy changes; backend remains authoritative regardless. HTML metadata and page titles use show name+episode code, never protected title.

## C08 — Notifications, moderation and account lifecycle

- GET /notifications → paginated with unreadCount (count of visible unread pending requests) alongside items/nextCursor; items `{id,kind:"follow_request",actor:Person,createdAt,readAt}`; return only still-valid pending requests, no protected episode text. PATCH /notifications/{id} `{read:true}` → 204, owner only 404 otherwise. A notification click opens Friends requests; resolved request shows empty resolved state. No reply notifications in this release.
- GET /operator/reports?state=open → paginated `{id,reason,commentId,discussionId,reportedBody,reporterId,createdAt}`. Operator role only, 403 for members. Operator reads are an explicit moderation exception to spoiler/host visibility, audit access and show spoiler warning.
- POST /operator/reports/{id}/resolve `{action:"remove_comment"|"dismiss"}` → 200 `{state:"resolved"|"dismissed"}`. Removal tombstones comment and resolves associated reports. Atomic audit; already resolved same decision idempotent, conflicting decision 409. No self-service operator promotion; deployment CLI maps an explicit user ID, documented/manual only.
- POST /me/export `{}` → 202 `{jobId:"uuid",state:"queued"}`. One active export/user, repeat returns active. GET /me/export/{jobId} → 200 `{state:"queued"|"running"|"ready"|"failed",expiresAt:null|"ISO"}`. GET /me/export/{jobId}/download → 200 application/json attachment; owner only, 404 cross-user, 409 not ready, 410 expired. Export includes own profile, library, progress, authored comments, follow/block relationships and own notifications; no other's private comments, credentials/session hashes/tokens. Artifact TTL24h, authenticated streaming, no public URL.
- DELETE /me `{confirmation:"DELETE"}` → 202 `{state:"deleting"}` with fresh password/Google reauth, exact confirmation. Immediately disable account/revoke sessions and grants; job erases personal data, identities, follows, progress, blocks, notifications, own exports and tokens within24h. Shared comments become anonymous bodyless tombstones; hosted threads removed from user access and comment bodies erased by cleanup. No automatic transfer of hosting. Operator audit retains only anonymous action/timestamp/report identifiers required for operational history. Backups expire within30d per runbook and restores must replay deletion ledger before serving. Delete is irreversible; UI explains it. Worker failure remains disabled and retries/alerts operator.

## C09 — Required test truth table

1. Mark E3 with E2 unmarked: E2 remains next; E3 details visible; E3 discussion locked until explicit discussion grant or gap filled.
2. Mark future E4: persisted watched, future label retained, no release metadata changed, next skips unreleased episodes. Undo reverses only E4 action fields.
3. Undated E2 marked or not: never included by catch-up, blocks Completed while release unresolved. If before discussion target and unmarked, gate remains locked.
4. Catch-up E5 with E1 already marked, E2/E3 released, E4 future, E5 undated: preview only E2/E3; exclusions explicit. Metadata changes before confirmation →409 and no writes.
5. Action A marks true, B marks false, C marks true: Undo A skips current field even though value equals A value. Bulk Undo preserves previously watched episodes.
6. No releases ≠ caught up. Ongoing all-released-watched = caught up. Ended complete known catalog and all regular marked = completed. Specials irrelevant to aggregate.
7. Viewer follows host one-way: no discussion listed. Mutual: listed but spoiler lock still applies. Reveal one thread does not open a second at same episode. Block/unfollow revokes access after reveal.
8. Private/public change immediately alters library access; block hides bilateral identities/content, including activity/notification payloads; unblock does not restore relationships.
9. Logout/reset revokes grants; different viewer/session cannot use cached protected data. Inspect JSON/SSR/prefetch/network for absent protected values, not only screenshots.
10. Duplicate signup/reset are enumeration-safe; Google equal email does not link automatically; token replay/expired nonce rejected; last-method unlink rejected.
11. Empty library/no follows still supports search→save→mark→next→undo. External provider down preserves saved progress and cached catalog.
12. Deletion disables access immediately and worker removes exports and personal rows; another user cannot download an export by guessing job ID.
